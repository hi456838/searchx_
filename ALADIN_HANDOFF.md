## 3. Reproducible demo datasets

### A. M101 · lead public case

**ICRS 210.80227°, +54.34895°.** Request a 0.10° square. The IRSA example returned D2 spectra across distinct weeks in DR1 and QR3. Its sample also shows some failed downloads. Use the notebook as evidence of coverage and as a recipe, then select the actual successful frames.

```sh
for collection in spherex_dr1 spherex_qr3; do
  curl --fail --get 'https://irsa.ipac.caltech.edu/SIA' \
    --data-urlencode "COLLECTION=$collection" \
    --data-urlencode 'POS=CIRCLE 210.80227 54.34895 0.01' \
    --data-urlencode 'TIME=60796 61222' \
    --data-urlencode 'MAXREC=100'
done
```

The UTC window is May 1, 2025 through July 1, 2026 at midnight. Parse VOTable results, including overflow status, and retain D2 rows. Narrow time windows if results overflow. If SIA is thin or unavailable, use the notebook’s TAP query at `https://irsa.ipac.caltech.edu/TAP`. It joins `spherex.artifact` to `spherex.plane` by `planeid`, uses `CONTAINS(POINT('ICRS',210.80227,54.34895),p.poly)`, filters `p.energy_bandpassname='SPHEREx-D2'`, and orders by `p.time_bounds_lower`. Use only current DR1 and QR3 URLs. Fetch each selected on-premises product with `?center=210.80227,54.34895d&size=0.1`.

**Pass:** Three distinct observation midpoints where available, same sky grid and stretch, valid core coverage, local wavelength overlap, and registration residual below 0.5 native pixel median on at least three stationary reference stars. Use the measured scatter in any change assessment. M101 is a stable-field registration/control story. **Fallback:** Ship two suitable exposures with a two-frame comparison, or label coverage and wavelength differences explicitly and show individual dated frames without quantitative comparison. ## 4. Wire contracts and mapping

Use one public envelope with integer `schema_version: 1`. The following field signatures describe JSON objects. A question mark means an optional field. Nullable values require an explanatory reason when they affect interpretation. No NaN or Infinity. Field-level JSON Schema should live beside the emitting adapter. Prefer existing SIEVE models after inspection and translate at the boundary.

| Record | Minimum required JSON fields |
|---|---|
| Observation | `id, exposure_id, detector, collection, processing_version, start_mjd, end_mjd, mid_mjd, time_scale, mid_utc, footprint_icrs_deg, source_url, cutout_url, fits_sha256, preview_url, preview_recipe_id, wavelength_um, bandwidth_um, status, reasons[]`. Wavelength and bandwidth are at the series center, with units in their names. `status` is `usable\|partial\|unusable\|fetch_error`. `mid_mjd` is in the supplied `time_scale`, and `mid_utc` is ISO 8601 with Z. Preserve actual archive times and observer metadata in FITS or the manifest. |
| Detection | `id, observation_id, ra_deg, dec_deg, epoch_year, flags[], producer, producer_revision`. Optional `sigma_arcsec, covariance_en_arcsec2, wavelength_um, bandwidth_um, flux` where flux is `{value, sigma, unit, method}`. Covariance is a 2×2 matrix in the local east/north tangent plane. Detection wavelengths are at the centroid. Use explicit `measurement_status` and `reasons[]` when measurements are incomplete. |
| Association | Embed the **unchanged native Identify v1.0 report** or reference it by verified URL/hash and join its `results[]` by `detection_id`. Preserve `status, reasons, flags, candidates, skipped, warnings, identity_confirmed, discovery_claim`. Candidate counterparts carry the native catalog ID, source URL, separation in arcsec, normalized separation and propagation metadata. Wrap service failures as `not_run\|unavailable\|error` outside the native report. |
| Candidate | `id, detection_ids[], hypothesis, status, reasons[], producer, producer_revision`. A time-domain hypothesis references at least two physically distinct observations. `status` is `proposed\|unresolved\|reviewed\|rejected`. Candidate membership changes produce a new ID. Association significance alone never changes candidate membership. |
| Harness Check | `id, run_id, candidate_id, method, method_revision, detection_ids[], execution_status, disposition, reason, evidence_url`. Optional `metrics[]` entries are `{name,value,unit}`. Execution is `not_run\|ok\|timeout\|error\|not_applicable`. Disposition is `consistent\|contradicted\|insufficient\|null`, with null for unexecuted checks. A successful runtime is separate from the scientific result. |
| Marker and Inspector | `Marker = {detection_id, observation_id, ra_deg, dec_deg, candidate_id?}`. `GET /api/v1/detections/{id}` returns `{schema_version,status,detection,observation,association,candidate,checks}`. Missing optional evidence is null/empty with its stage status. Unknown IDs return 404. Build track positions from referenced measured detections. |

IDs must be opaque, stable, and safe for URL encoding. Scope archive `exposure_id` to the mission physical observation. Scope product `id` to exposure, detector, processing version, and cutout geometry. Deduplicate reprocessing of the same exposure+detector and group simultaneous detector observations as a single epoch. Detections link to the exact cutout used. Use upstream persistent detection IDs, or derive from immutable product ID, producer revision and deterministic source key. Cache by archive product/version, exact cutout geometry and preview recipe.

**Identify bridge.** Call `identify(detections, catalog, {radius_arcsec, max_normalized_separation})` from the pinned `src/identify.js`. Project detections to `{id,ra_deg,dec_deg,epoch_year,sigma_arcsec?,flags?}`. Coordinates are ICRS degrees with RA in [0,360). Epoch is a decimal Julian year, computed from time using Astropy `Time(...).tt.jyear`, with the same convention for externally propagated catalog rows. Omit unknown isotropic one-axis sigma from the matcher input. Its validator rejects null or nonpositive sigma. Catalog rows require `id,catalog,source_url,ra_deg,dec_deg,epoch_year` and allow `sigma_arcsec,flags,label,object_type,pmra_mas_yr,pmdec_mas_yr`. Proper-motion components must be paired. Retain catalog version, query scope, hashes, and original epoch in outer provenance. Use a comparable per-epoch catalog subset with defensible errors. Missing epoch coverage can make a whole match inconclusive in this implementation. Preserve the four native statuses and both false claim fields. [Pinned matcher](https://github.com/hi456838/searchx-identify/blob/7c24aeead8587215f9f9c73c0db51e2e17043cc8/src/identify.js)

**Harness bridge.** Preserve numeric `schema_version: 1`, `case_id`, and `backends` on the runner input. Build it from registered assets and an applicable configured adapter. For the documented HelioLinX lane that means `catalog_csv,column_format,earth_ephemeris,observatory_codes,hypotheses,reference_mjd`; verify geometry and cadence before choosing it. Confirm the actual runner and output with its owner. `python3 harness_runner.py path/to/case.json` is the documented invocation. Use narrow independent checks if full linking is inapplicable. The six-project sample is a fixture suite and its outputs do not establish cross-verification of one candidate. [Harness input guide](https://drive.google.com/file/d/1QxdYlECjs-BJuko6htNTpEE7iiRuOPhH/view)

**Series HTTP.** `GET /api/v1/series?ra_deg=210.80227&dec_deg=54.34895&size_deg=0.1` returns `{schema_version,series_id,field,source, status,observations[],markers[],reasons[]}`. `field` echoes ICRS center and size. `source` is `live\|cache`. `status` is `ready\|partial\|no_coverage\|unavailable`. Include comparable-group metadata in the manifest. Return 400 for invalid coordinates or size, and 503 when the archive is unavailable and there is no matching cache. A valid empty field returns 200 with its explicit state. Start with 0.10° maximum cutout and 12 frames, bounded serial or two-way upstream concurrency, and a per-request deadline. Keep a cache path independent of the live request.
